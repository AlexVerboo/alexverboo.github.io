Lab · Personal project · Nov 2026

snakemagic.com · From Hacked WordPress to a Static Site

Rescue and migration of snakemagic.com, a friend's website (a video comedy project from 2014–2016) that was still on paid shared hosting with auto-renewal and a malware-cleaning add-on. I audited the server, found the WordPress install was compromised, backed up only the clean content, rebuilt the site as a static page on GitHub Pages, moved the DNS and closed the hosting account. I then negotiated with the provider and secured a 100% refund of the annual renewal.

My role

Individual project, done voluntarily to help a friend. I handled everything end to end: technical audit, backups, building the new site, DNS cutover, closing the hosting account and negotiating with the provider. I used Claude (Anthropic) as an assistant for the audit and documentation. The site owner authorized the access and agreed to this project appearing on my CV.

Problem and context

  • The site hadn't changed since 2016, yet shared hosting and a malware-cleaning service were paid for every year.
  • Auto-renewal was on, and the plan renewed in October 2026 without the owner wanting it.
  • The site got infected several times a year despite the paid cleanup.
  • The embedded Vimeo videos were no longer available; some originals existed only on the server.

Sources reviewed: the server files (about 525 MB), the WordPress MySQL database (13.6 MB), 69 files in wp-content/uploads, MP4 videos, the ClamAV report and quarantine folder, and the DNS zone in the hosting and registrar panels.

Before and after

Process

  1. Hosting audit Reviewed contracted services, access, users, SSH keys, FTP, cron, email and DNS to see what was being paid for and what was actually used.
  2. Security analysis Identified the indicators of compromise: PHP scripts in uploads, randomly named files, a fake plugin and theme, quarantined files and the ClamAV report. Decided not to restore or run anything from the WordPress install.
  3. Selective backup Saved only the clean content (videos, images and database) before closing the account.
  4. Rebuild Built a static HTML and CSS site with the video intro, cast clips and contact info, published on GitHub Pages.
  5. DNS migration Moved the domain off the old hosting nameservers and set up A and CNAME records to GitHub Pages plus the custom domain, with HTTPS.
  6. Hosting shutdown and refund Turned off auto-renewal, cancelled the account and negotiated with support: the paid malware service had not cleaned the infection. The supervisor approved a full refund as an exception to policy.
  7. Registrar cost review Found an SSL certificate being paid for but unused, and turned off its auto-renewal.
  8. Handover Sent the owner a before-and-after report written for a non-technical reader.

Takeaway: for sites that rarely change, static hosting is cheaper, safer and easier to maintain than a CMS, and reviewing subscriptions and auto-renewals can save real money.
